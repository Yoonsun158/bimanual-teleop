# 2026-09-15 15:11 实机遥操作故障分析

> 以下是修改控制算法前对原始日志的分析。后续实现和验证已完成，见[修复说明](teleop_servo_20260915.md)；原始证据保留不变。

## 结论

本次 7 条 IK 暂停全部来自右臂（当前映射由左手柄控制）：1 次 J4、1 次 J6、5 次 J1。固定 SDK 和模型重放后，7 条结果与日志逐关节完全一致，误差为 0°。

**第 1 条确实越过关节可达边界；其余 6 条存在保持同一末端目标的合法近邻关节解，直接原因是当前冗余姿态选解不合适。** 现有程序任一臂 IK 拒绝都会触发双臂及双手联合暂停，形成整个系统卡住的体验。本次没有出现已撤回的 `step bounds` 错误。

计算证据：[完整输入、结果和对照](teleop_ik_20260915_1511_evidence.json)。本轮仅执行本地运动学，没有连接设备、改变控制算法或下发候选解。

这些另解均通过 SDK 标志、模型限位、腕部耦合有效边界及 FK 回代检查。最大位置误差小于 0.000042 mm，朝向误差小于 0.000020°。每个独立快照内部另作 64 段位置直线、朝向短弧及冗余角插值，采样点均合法。这个采样验证不构成整条连续曲线的严格证明，也不是现场整段轨迹或 5 ms 速度、加速度及碰撞验证。

第 2、7 条的候选仍明显贴近限位；它们证明“存在另解”，不适合原样作为持续遥操作的姿态策略。生产求解必须考虑接下来运动的余量，不能只在越限那一帧勉强找到合法角度。

## 1. 第一次是过度折叠的可达边界

模型规定 J4 为 `[-145°, +60°]`。该目标的两个肘部弯曲分支分别是：

```text
−145.035657°
+131.296370°
```

两者均越限。改变肘部冗余角不会改变这个目标需要的 J4。因此本次不能靠“换另一组关节角”精确完成原目标。

相对配置中的初始姿态，该目标沿右臂基座 X 已后移约 417 mm，进入深度折叠区域。此处应按真实关节可达边界处理目标推进。增加搜索次数、放宽判断精度或单独切换参考关节都不能改变物理可达性。

SDK 的 `status=0`、`out_of_range=0` 不代表通过全部约束：它能算出几何解，但 `limit_mask=8` 已明确指出 J4 越限。

## 2. 后续是冗余姿态选择和肩角敏感性

第 3 条最明显：原解要求 J1 从 −161.037° 变为 −172.861°（−11.824°），同时 J3 增加 11.654°。但同一末端目标可以选成：

```text
J1: −161.037251° → −160.630044°，只需 +0.407208°
J3: +120.703221° → +121.687919°，只需 +0.984698°
其余关节中，最大变化为 J5 的 +1.550522°。
```

说明大幅肩关节变化和 J1 越限不是完成该目标的必然要求。此时 J1/J3 轴夹角约 11.24°，之后 J2 进一步接近 −5°，当前肘平面策略下的肩关节角分解更敏感。完整七关节雅可比数值计算仍满秩，因此不能把这些故障一概称为“整台机械臂进入不可解奇异点”；`singular_mask=0` 也不能证明所选姿态远离敏感区域。

本次目标并非始终只有微小变化：第 3 条实际变化了 4.81 mm / 2.09°。缺少前一命令时刻，无法判断这个变化来自手部运动速度还是源采样/插值节奏；合法另解的存在则已经得到独立验证。

## 3. 为什么按 Enter 很快再次暂停

接合从实际关节建立新参考，不会回到初始姿态。后 3 次快照实际 J1 为 −167.8515°、−167.8516°、−167.8541°，距模型下限约 2.15°。重新接合后仅 15 / 17 / 17 个命令步，旧选解方式又把目标推到 J1 下限。

前 3 次实际关节与上一接受的参考关节最大差约 12.37–14.43°；实际末端与目标的距离为 12.09–22.01 mm、姿态差为 4.93–8.78°。在笛卡尔阻抗控制下，已接受命令不等于实际姿态。单靠这些离散快照还不能区分动态跟随、阻抗偏差、负载或其他机械因素。

只把每帧参考改成实际关节也不是完整修复：7 个相同目标中只有第 2、3、4、6 条因此变合法，第 1、5、7 条仍失败；部分解相对实际姿态仍需改变 7.68–16.36°。不能用这种替换直接绕过连续运动验证。

## 4. 最后一次反馈错误尚不能定因

`Invalid Tianji feedback or controller error` 来自 [quest.py](../bimanual_teleop/control/arm/quest.py)，会合并以下条件：

- 任一所选臂控制器 `error != 0`；
- 关节位置或速度含无效值；
- 双臂模式下整体反馈 `valid=False`。解码器还将测量力矩、估计外力矩、控制器目标、电流中的非有限值计为无效。

已离线注入验证：控制器错误码为 0，位置和速度正常，仅电流或估计外力矩一个 NaN，也会出现同一句提示。本次没有记录触发包的字段，不能确定哪侧、哪个错误码或是否硬件故障。

后几次 J1 实测值接近不变，但其他关节仍在变化；主机 SDK 未找到 −167.85° 的固定夹限逻辑。不能据此认定碰撞、编码器损坏或某个固件软限位。

Wuji 的 `Enc1BitRate` 和启动订阅积压不能解释上述可精确重放的 7 次 IK 限位。退出时 ADB `−2` 表示 SIGINT，可由 Ctrl+C 引起，不能将其当作此前暂停的断线证据。

## 修正方向

1. 对 J1/J6 这类选解问题，在核心求解中明确连续性、肩肘姿态和限位余量，避免靠近边界后才临时换解。已经有本次实测目标可作回归依据。
2. 对 J4 这类真正越过关节可达边界的目标，采用受约束的任务推进，允许暂时跟踪误差并让退出边界的动作仍可执行；不能要求任意原目标当帧精确实现。
3. 将反馈故障记录为具体侧别、控制器错误码及无效字段，单独定位最后一次故障。不要根据笼统提示调整控制参数。

当前证据足以区分主要故障机制；完整实机运动效果仍需在实现相应控制策略后验证，不能从这些单次合法候选直接推断。
