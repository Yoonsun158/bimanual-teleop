# Tianji 遥操作核心控制修复（2026-09-15）

## 结论与适用范围

已将遥操作和预览的逐帧 `NEAR_REF` 精确 IK 改为受约束的笛卡尔速度求解。目标推进、冗余关节姿态、关节位置、速度、加速度及腕部耦合在同一个优化问题内处理。目标不能立即实现时缩小推进速度，不把普通不可达目标变成双臂／双手暂停。

本次依据用户 15:11 运行的七条独立故障快照。六条存在合法近邻解，另一条 J4 两个弯曲分支均越限；详见[原始日志分析](teleop_ik_20260915_1511.md)。这七条不能拼成连续实机轨迹。原始证据文件保留，新的[离线验证结果](teleop_servo_validation_20260915.json)另存。

所有验证均使用本地固定版本厂家运动学、模拟采集和模拟驱动，未连接机器人或下发实机命令。本文不将理想指令轨迹等同于真实机械运动。

## 具体修改

1. **连续运动从完整雅可比求解。** 使用厂家 6×7 几何雅可比，避免依赖 `NEAR_REF` 的肩角分解和几何分支跳变。接合参考来自驱动实际采用的反馈包；姿态偏好锚定该测量姿态，不复制官方固定肘方向。只有双方提案都有效且整组发送成功，才更新指令关节和速度状态。
2. **目标推进可缩小，关节约束不可放宽。** 七关节位置、按配置比例缩放的速度／加速度，以及四个 J6/J7 耦合面均为硬约束。真正不可达的目标停在边界附近；目标返回可达范围后继续跟随。长时间将手柄推到工作空间之外会留下位姿误差，回撤仍需消除这段误差；没有自动重新映射手柄零点。
3. **保持请求方向并允许刹车。** 普通软最小二乘在一个折叠边界反例中产生了约 18.6 mm 未请求侧移和 2.3° 转腕，因此未采用。当前等式只允许目标方向与已有运动的刹车方向，冗余偏好只能在零空间作用。非线性离散积分仍存在小量误差，不能把一阶方向约束称为严格全程直线轨迹。
4. **时基统一。** 积分、速度和加速度使用相邻命令计算开始时刻之间的真实间隔，首步为名义 5 ms；不扣掉上次提交耗时、不将迟到帧硬截为 5 ms。源数据期限和驱动 watchdog 保持有效，过期目标不会因新控制方法续命。
5. **区分目标与下发结果。** `goals` 保存输入目标，`requested_target` 保存采样目标，`commands`／`preview` 和 `last_target` 为下发关节对应的 FK 位姿。状态包含位置、姿态误差和 `max_joint_tracking_error_rad`，后者仅作观测。持续受限超过半秒才提示一次，并明确仍处于接合状态。
6. **反馈故障具体分类。** 位置、速度、控制器目标无效及控制器错误继续锁存暂停；报告臂侧、关节序号、错误码、反馈序号和时间。电流、测量力矩、估计外力矩缺失保留 `None`，单独报告观察数据缺失，不再触发同一条笼统暂停。错误包后紧跟正常包也不会自动恢复运动。

新控制故障输出 `[控制诊断]`，包含 `q_rad`、`velocity_rad_s`、`anchor_rad`、`dt_s`、目标位姿、速度／加速度比例、SDK／模型版本及原始异常；执行器补充源样本、命令时限和最近反馈。历史 `[IK诊断]` 与 `scripts/analyze_tianji_ik.py` 保留供精确 IK 的离线分析，两种快照不能混用。

## 核心约束为何始终保留刹车解

令固定的位置约束为 `Cq ≤ b`，包含关节上下限和全部腕部耦合面。令 `k = min(amax / vmax)`，每步施加：

```text
(1 + k·dt) C v ≤ k (b − C q)
−vmax ≤ v ≤ vmax
−amax·dt ≤ v − vprev ≤ amax·dt
qnext = q + dt·v
```

这保证更新后 `Cv ≤ k(b − Cqnext)`。下一步的共同刹车速度 `vbrake = vprev / (1 + k·dt)` 同时满足所有位置面、速度和加速度约束。因此不会因不同关节各自刹停、腕部耦合或采样间隔变化而凭空制造不可行问题。前提是初始状态合法、初始速度为零、仅成功发送后推进状态。

笛卡尔等式为 `Jv = α·vgoal + β·Jvbrake`，`α,β∈[0,1]`。`α=0,β=1,v=vbrake` 是可行候选；静止时退化为目标方向上的速度缩放。实际数值实现先归一化两个方向，再消去齐次等式，缩放目标二次型和约束行，通常只需解三变量严格凸 QP。

最终使用单一 **Quadprog 0.1.13 / Goldfarb–Idnani 活动集求解器**，没有多求解器重试或事后裁剪关节。ADMM／近端迭代求解器在接近平行／反向的方向列及活跃限位下曾误报无解；即使固定矩阵求解成功，也必须通过整个闭环回放。输出在原始单位中再次验证残差和协议角度。

SDK 发送每个关节角时转换为 float32 度数。J6/J7 独立舍入会使耦合面最大向外偏约 `5.77×10⁻⁶°`，因此耦合面保留 `10⁻⁵°` 数值余量，并检查量化后命令。这个极薄范围内的接合初值会被明确拒绝，错误包含实际余量；不会擅自调整测量姿态。

最终完整回归：**491 项 Python 测试全部通过，原生桥接 CTest 1/1 通过，依赖检查与 `git diff --check` 通过**。Conda 依赖和本机原生库已更新。

- 固定 SDK：`02440e886fb59095711eb9ec6dcbedd8be08922a`；模型 SHA256：`ce20b1a80974c3ed58cdac4973152625096c8ad93a779e5fd4108c26ce19bd52`。
- 七条独立实测参考各推进约 3 秒。六个可达目标均收敛；J4 超界目标保持合法且持续报告受限，回到原可达位姿后恢复。结果没有把替代解直接一步下发。
- 两侧四个腕面、近限静止和微噪声、肩角敏感姿态、持续超界推压、反向退出、循环轨迹、5/10/20 ms 及随机 1–20 ms、1 ns／零间隔、不同速度／加速度比例逐帧检查 q/v/a。提交失败、第二臂失败或源故障均不得推进任一臂状态。
- 90 Hz 六轴输入经过实际映射／滤波／重采样，以 200 Hz 发送，注入 10/20 ms 迟到和 3 ms 提交耗时；同时检查期限制约及实际发布位姿。
- 全部采样中的指令 q/v/a 和耦合边界验证不能替代真实控制器动态验证。协议量化后的差分速度／加速度还存在浮点误差。
- 比例增益选择 16/s。独立六轴轨迹在 25% 速度／40% 加速度配置下最大位置误差约左 10.76 mm、右 12.64 mm。默认配置的小阶跃测试没有可测超调；72 组不同采样间隔和较低加速度配置中，最大小幅超调约 0.273 mm／1.365°，最终均停稳。
- 直接令目标速度为 `位姿误差/dt` 曾使 50 mm 请求超调约 39.6 mm，因此没有采用；也没有为消除静态过冲叠加会拖慢所有连续运动的目标减速层。

时延测量见验证 JSON；它是本机进程的离线耗时统计，不是硬实时保证。数值依赖在驱动开始首命令 watchdog 前加载，模块导入本身仍无设备访问或外部库初始化。

## 研究依据与差异

- [Wuji 官方 Tianji 实现](https://github.com/wuji-technology/wuji-hand-teleop/tree/647801345a6a27dec5cbf56280ce63bb8b2f6a32/src/output_devices)：确有使用天机机械臂的仓库，但它的参考肘方向、追踪器和模型边界不能直接照搬。没有找到与本次故障完全对应的已解决 issue。
- [SNS（Flacco 等，T-RO 2015）](https://iris.uniroma1.it/retrieve/e383532a-4954-15e8-e053-a505fe0a3de9/Flacco_Postprint_Control-of-Redundant_2015.pdf)：参考其关节约束下缩放任务速度、保持方向的原则。本文的共同刹车方向和具体数值实现属于本项目适配，不声称完整复刻 SNS。
- [DROID 的笛卡尔速度控制](https://github.com/droid-dataset/droid/blob/33ae6a67274f36d2e29525b86f23a56616ef43a7/droid/robot_ik/robot_ik_solver.py)及 [Pink](https://github.com/stephane-caron/pink)：参考其将目标跟踪与硬关节约束分开的做法。
- [Quadprog 官方实现](https://github.com/quadprog/quadprog)：严格凸 QP 的 Goldfarb–Idnani 活动集算法。

## 环境与实机仍需确认的部分

项目依赖统一安装在 Conda `bimanual-teleop`，新增 Quadprog 并明确运行时 NumPy／SciPy 依赖。环境设置 `PYTHONNOUSERSITE=1`，避免用户级包覆盖项目依赖；旧环境需更新依赖并重新激活。桥接库新增雅可比接口，升级必须重新编译。

本次日志中实测关节曾落后指令约 14°，原因仍不能从离散快照唯一确定。当前没有为此擅改阻抗、负载、初始位姿或硬件限位，也未加入未经标定的跟踪误差夹限。现有硬件故障、追踪丢失、模式异常及超时停机仍有效。碰撞、实体干涉、负载与阻抗跟随效果需要实机确认，当前实现没有全机碰撞模型。
